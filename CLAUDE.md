# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Obsidian community plugin ("Smart DayNight switcher", id `smart-day-night-switcher`) that computes local sunrise/sunset from user-entered latitude/longitude and toggles Obsidian between light and dark color schemes. The repo is checked out directly inside a dev vault's `.obsidian/plugins/` folder, so a build output (`main.js`) is picked up by that vault on reload.

## Commands

- `npm run dev` — esbuild in watch mode, writes `main.js` with inline sourcemaps.
- `npm run build` — type-check (`tsc -noEmit -skipLibCheck`) then minified production bundle to `main.js`.
- `npm run lint` — ESLint over `src/` and `test/` (config in `.eslintrc`).
- `npm test` — Vitest, single run. `npm run test:watch` for watch mode; `npx vitest run test/sun-times.test.ts` or `-t "<name>"` for one file/test.
- `npm run generate:time-zones [-- <tzdata dir>]` — regenerates `src/time-zones.ts` from the system tz database (`/usr/share/zoneinfo` by default: `zone.tab`, `tzdata.zi`) plus every name `Intl` supports. Re-run occasionally to pick up new zones.
- `npm version <patch|minor|major>` — bumps `package.json`, then `version-bump.mjs` syncs `manifest.json` version and adds an entry to `versions.json` (version → `minAppVersion`). Keep these three files in sync when releasing.
- `npm run release -- <patch|minor|major>` — `release.mjs`: requires a clean `master` in sync with origin, runs lint/test/build, then `npm version`, pushes commit + tag, and creates the GitHub release (tag = version, no `v` prefix) with `main.js`, `manifest.json` and `styles.css` attached via `gh`.

## Testing

README.md is the spec: tests should assert what it promises, not implementation details. `test/sun-times.test.ts` checks "light while the sun is up" against `SunCalc.getPosition` for cities across time zones and polar latitudes, independent of `getSunTimes`.


Vitest + happy-dom, configured in `vitest.config.mts` (`.mts` because the package isn't `"type": "module"`). Tests live in `test/*.test.ts`. Vitest 5 needs Node `^22.12 || ^24 || >=26` (see `engines`). `tsconfig.json` includes `**/*.ts`, so `npm run build` also type-checks the tests.

- **`obsidian` is stubbed.** The npm package is types-only, so `resolve.alias` points it at `test/__mocks__/obsidian.ts` (`requestUrl`, which always rejects — tests `vi.mock` it or `../src/locate`; `Plugin` with `registerInterval`/`addCommand`/`unload()` — call `plugin.unload()` in tests, not `onunload()`, so registered intervals are cleared — `PluginSettingTab`, `Setting` with Obsidian's `.setting-item` markup plus `setHeading`/`addText`/`addToggle`/`addButton`/`addDropdown`, `Notice`, `debounce`). Tests are type-checked against the real typings, so keep the stub's signatures compatible; add to it when source starts using more of the API.
- **Obsidian's DOM helpers** (`createEl`, `empty`, `setCssStyles`) are polyfilled on `HTMLElement.prototype` in `test/setup.ts`.
- **Timezone is pinned to `Europe/London`** in the config, so expected local times (e.g. London sunrise `04:44` on 21 Jun 2026) are stable on any machine. Use `vi.useFakeTimers()` + `vi.setSystemTime()` for anything that reads the clock or schedules timers.
- `test/helpers.ts` → `createPlugin(savedData)` builds an `SDNSPlugin` with a fake `app` and spied `loadData`/`saveData`. `savedData` defaults to `{}`; pass `null` for a fresh install, which guesses coordinates from the (pinned) time zone. `stubTimeZone(zone)` fakes `Intl`'s time zone (undo with `vi.unstubAllGlobals()`); spying on `Intl.DateTimeFormat.prototype` doesn't take effect under happy-dom. Note `defaultColorScheme` is captured at construction, so set `document.body` classes before creating the plugin.

## Architecture

Source lives in `src/`, entry `src/main.ts` (bundled by `esbuild.config.mjs` to CommonJS at the repo root `main.js`, `obsidian`/`electron`/CodeMirror externals).

- **`main.ts` — `SDNSPlugin`** (SDNS = Smart DayNight Switcher):
  - On load, records the user's current scheme (`defaultColorScheme`) so `onunload` can restore it. `loadSettings()` on a fresh install (`loadData()` returns nothing) replaces the London defaults with `guessFromTimeZone()` in memory; `onload` then, without awaiting, tries `locateByIp()` and saves whichever location it ends up with, so the guess happens once (unless the plugin unloads first). An IP answer is ignored if the coordinates changed meanwhile.
  - While `settings.paused`, `checkAndSwitchColorScheme()` restores `defaultColorScheme` and schedules nothing. The `toggle-pause` command (`TOGGLE_PAUSE_COMMAND` in `settings.ts`) flips `paused` via `togglePause()`, then calls the settings tab's `update()` so an open tab shows it (its toggle's `onChange` ignores the no-op that Obsidian's `setValue()` fires).
  - `checkAndSwitchColorScheme()` asks `getSchemeState()` for the current scheme and the delay until the next transition, applies it, then schedules a single `setTimeout` that calls itself again. Any existing timeout is cleared first, so it is safe to call repeatedly (e.g. from `saveSettings`).
  - Timers don't advance while the computer sleeps, so `onload` also registers a once-a-minute interval (`registerInterval`) that re-runs the check if the wall clock has passed `nextChangeAt`.
- **`sun-times.ts`** — pure SunCalc wrappers (no DOM/Obsidian imports, so unit-testable): `getSunTimes()` (SunCalc's `sunrise`/`sunset`, per the README: light when the sun rises, dark when it sets), `getSwitchTimes()` (sunrise/sunset shifted by the user's `Offsets` in minutes), `getSchemeState()` (collects switch events for ±2 days; adjacent opposite events that offsets push to or past each other cancel out, so a vanished day/night keeps the surrounding scheme; the scheme is the type of the last event, the delay runs to the next opposite event, capped at a day; during polar day/night it picks by sun altitude vs −0.833° and re-checks within an hour, so the delay is never `NaN`, which `setTimeout` would treat as 0 and loop), `getNextSwitch()` (time and scheme of the next change, for the settings status line; `null` during polar day/night), `getSchedule()` for the settings table.
- **`locate.ts`** — the only network code, via Obsidian's `requestUrl` with a 10 s timeout; failures return `null`. `locateByIp()` asks GeoJS (keyless, no rate limit) for the IP's city, coordinates and "City, Country" name (`null` without a city). `lookUpPlaceName()` reverse-geocodes with OpenStreetMap Nominatim (max 1 request/s, needs an identifying User-Agent and OSM attribution, which the settings help shows).
- **`time-zone.ts`** — `guessFromTimeZone()`: coordinates of the principal city of the `Intl` time zone, or `null` (UTC, `Etc/*`, unknown). Data is the generated `time-zones.ts` (don't edit by hand), keyed by current and legacy names, since Electron may report e.g. `Europe/Kiev`.
- **`color-scheme.ts`** — `getColorScheme()` / `setColorScheme()`; switches by toggling `theme-light`/`theme-dark` classes on `document.body` and triggering the workspace `css-change` event; it does not change Obsidian's persisted appearance setting.
- **`settings.ts`** — settings interface and defaults (London; `paused: false`). Latitude/longitude are stored as strings; `locationName` is the place's name, `""` while unknown; `parseCoordinates()` turns them into numbers, or `null` if empty, non-numeric or out of range. Sunrise/sunset offsets are strings too; `parseOffsets()` treats empty, invalid or beyond ±180 min as 0. While it is `null` the scheduler does nothing and the settings tab shows a hint instead of the table. `parseCoordinatesInput()` splits the settings tab's single "lat, lng" field into the two strings, or returns an error message.
- **`settings-tab.ts` — `SDNSPluginSettingTab`**: builds the UI with Obsidian's `createEl`/`Setting` APIs (avoid `innerHTML` and inline styles, which Obsidian's plugin review flags; styling lives in `styles.css` under `sdns-` classes). A status line (current mode and next switch, or paused), a pause toggle with a "Set hotkey" button (opens Settings → Hotkeys through the undocumented `app.setting.openTabById`, sets the search box to "DayNight" and fires an `input` event, like typing, since the tab's own refresh methods were renamed across versions; each step optional so an API change degrades quietly), then headed sections: Location (one "lat, lng" text field with a "Place: …" line and an inline error; typing clears the name and looks it up with `lookUpPlaceName()` 1.5 s after the last change, opening the tab looks up a missing name once per coordinates, and a failed lookup shows "impossible to calculate"; a "Guess from IP address" button; a "Guess from time zone" button that fills in `guessFromTimeZone()` and is disabled while those coordinates are in use, plus collapsed help), Offsets (per event: a 0–180 minutes number field plus a before/after dropdown, stored as a signed string; out-of-range input shows a red description and isn't saved) and Schedule (7 days, expandable to 31). Inputs save through Obsidian's `debounce`; invalid coordinates are not saved, so switching continues with the last valid location. After each save `refresh()` re-renders only the status line and schedule, so the input being edited keeps focus.
- **`format.ts`** — pure date/time formatting for the table.

`styles.css` holds the settings tab styles and is attached to GitHub releases by `release.mjs`. `ts-debounce` is listed as a dependency but the code uses Obsidian's built-in `debounce`.
